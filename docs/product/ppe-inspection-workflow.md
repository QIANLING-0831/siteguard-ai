# 安全帽专项巡检流程

## 责任边界

- 视觉适配器只产生待人工确认的 `Finding`，并记录模型名与置信度。
- 安全员查看原始证据和目标框后，确认或驳回 Finding。
- 只有人工确认才能创建 `HazardCase`，随后指定责任人和整改期限形成 `RectificationOrder`。
- 责任人提交整改证据，复核人通过或退回；只有复核通过才能 `Closure`。
- 所有状态变更写入审计事件，关闭不删除历史证据。

## 企业批次

一次 `Inspection` 是有项目、执行人、时间和范围的巡检批次。一个批次可以接收多个固定摄像头、移动摄像头、本机采集或上传来源的多份 `Evidence`。每份证据可包含多个临时 `ObservedPerson`，不做人脸识别，也不建立实名人员档案。

当前工作台按以下队列组织：

1. 待人工确认：显示每条 Finding 自己的原图和人员红框。
2. 待派单：人工确认后选择项目成员和整改期限。
3. 整改/复核：责任人接单、提交整改后照片，复核人对比整改前后证据。
4. 已关闭：保留 Finding、隐患、整改单、证据和复核历史。

## 依据与限制

《中华人民共和国安全生产法》第四十五条要求生产经营单位提供合规劳动防护用品并监督、教育从业人员正确佩戴；第四十六条要求安全管理人员经常性检查，并如实记录检查及处理情况。产品因此把 AI 定位为巡检辅助，不替代企业安全管理人员的判断和记录责任。
